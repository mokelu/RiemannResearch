# Chapter 6 — Linguistic Event-Driven Engine (LEDEN)

## 6.1 What Is LEDEN?

**LEDEN (Linguistic Event-Driven Engine) is the event-driven system that allows linguistic instructions to become reactive behavior.**

It connects language to events in the World.

For example:

```text
When the Button is pressed,
tell AI.
```

LEDEN allows the system to recognize that the Button has been pressed and trigger the corresponding instruction.

## 6.2 Events

LEDEN works with events and patterns such as:

```text
Button was pressed.
Chart crossed SMA.
Spreadsheet changed.
Workspace became active.
```

It can also handle more complex conditions:

```text
Button was pressed 3 times
within 10 seconds
after Chart crossed SMA
while Workspace is editing.
```

These are event relationships that can be evaluated by the event-processing system.

## 6.3 Linguistic Instructions Become Reactive

A Symphony can describe an event-driven instruction:

```text
When Button is pressed,
tell AI.
```

LEDEN connects that instruction to the World.

When the event occurs:

```text
Button → pressed
```

the corresponding behavior is triggered:

```text
Button → tell → AI
```

The system therefore does not need to continuously ask an AI what should happen.

The instruction has already been installed, and LEDEN reacts when its conditions occur.

## 6.4 LEDEN and Computational Engines

LEDEN does not have to perform every type of computation itself.

It can work with specialized engines such as:

```text
Algebra
CEP
Probability
AI
```

For example, a complex temporal pattern can be handled by a CEP engine while deterministic state changes are handled by an algebraic machine.

LEDEN connects these computations to the linguistic instructions being executed.

## 6.5 The Key Idea

> **LEDEN turns linguistic instructions into event-driven behavior, allowing computational selves to react to what happens in the World.**


# Chapter 6 — Linguistic Event-Driven Engine (LEDEN)

## 6.1 What Is LEDEN?

**LEDEN (Linguistic Event-Driven Engine) is the event-driven substrate that allows linguistic instructions to become reactive behavior.**

It connects the language of a Symphony to events occurring in the World.

For example:

```text
When Button is pressed
within 10 seconds
after Chart crossed SMA
tell AI.
```

LEDEN allows the system to recognize when the conditions described by the Symphony have occurred.

---

## 6.2 Language Meets Events

Traditional event-driven systems usually work with predefined programming events:

```text
click
change
submit
keydown
```

LEDEN extends this idea to linguistic events.

A Symphony can describe events in terms closer to how people naturally describe them:

```text
Button is pressed
Chart crossed SMA
Workspace is editing
```

LEDEN connects these descriptions to actual events and state changes in the World.

---

## 6.3 LEDEN Uses Existing Engines

LEDEN does not need to reinvent every form of event processing.

It can use existing computational engines for the particular kinds of reasoning required.

For example:

```text
LEDEN
  │
  ├── CEP → event and temporal reasoning
  ├── Algebra → deterministic state
  ├── Probabilistic systems → uncertainty
  └── AI → general reasoning
```

LEDEN provides the linguistic layer that connects these capabilities.

---

## 6.4 From Instruction to Reaction

Consider:

```text
When Button is pressed,
tell AI.
```

The instruction is installed into the relevant self.

The system then waits for the corresponding event.

When the Button becomes pressed:

```text
Button pressed
      ↓
LEDEN
      ↓
instruction matches
      ↓
Button tells AI
```

The AI does not need to continuously monitor the Button.

The event-driven system handles the reaction.

---

## 6.5 The Key Idea

> **LEDEN makes language event-driven: linguistic instructions can remain active in the World and react when the events they describe occur.**
