Then comes the really interesting idea: projections or perspectives or views or lenses.

This is one of the most important parts of Riemann.
You have one underlying structure (the JSON).
You can look at it in different ways.

Think of a house.
The house is one thing.
You can look at:

```text
front view
side view
floor plan
3D view
```

The house didn't change.
Your view changed.

Riemann with this JSON is doing something similar.

Here is the little structure we will look at in every view:

```text
ASSUMPTION    John is a dog.
CONSEQUENCE   John has four legs.
INFERENCE     John is an animal.
EVIDENCE      I saw John walking on four legs.

John is a dog.            implies    John has four legs.
John has four legs.       implies    John is an animal.
I saw John walking...     leans on   John has four legs.
```

1. The document view

The structure read as plain writing, sentence by sentence:

```text
John is a dog. So John has four legs.
I saw John walking on four legs, and so John is an animal.
```

It looks like a normal paragraph. It isn't one — every sentence in it is still
a node with a tag, and the words "so" and "and" are the relations showing
themselves as English.

2. The graph view

The same nodes as boxes, the same relations as arrows:

```text
ASSUMPTION ──implies──▶ CONSEQUENCE ──implies──▶ INFERENCE
                              ▲
                              │ leans on
                          EVIDENCE
```

Now the shape of the reasoning is the thing you see, not a paragraph about it.

3. The table view

One row per node, one column per thing a node has:

```text
id   text                           tag          connections
n1   John is a dog.                 ASSUMPTION   implies → n2
n2   John has four legs.            CONSEQUENCE  implies → n3, leaned on by e1
n3   John is an animal.             INFERENCE    implied by n2
e1   I saw John walking on four...  EVIDENCE     leans on → n2
```

Good for scanning: sort by tag, count what has no proof, find the lonely nodes.

4. The cells view

One card per sentence, stacked like a notebook:

```text
┌ ASSUMPTION ────────────────────┐
│ John is a dog.                 │
└────────────────────────────────┘
┌ EVIDENCE ──────────────────────┐
│ I saw John walking on four...  │
└────────────────────────────────┘
```

But a cell is not a text box. What you type in the cell IS the node's sentence.
Edit it there and the graph, the table and the document all change with it.

5. The canvas view

The graph again, but loose: you drag the nodes wherever you want and the
arrows follow your hand. Where a node sits is your choice, not the structure's
— the same connections, laid out the way *you* think about them.

6. The timeline view

The same nodes ordered by when they entered the research:

```text
Day/Time 1   ASSUMPTION   John is a dog.
Day/Time 2   CONSEQUENCE  John has four legs.
Day/Time 3   EVIDENCE     I saw John walking on four legs.
Day/Time 4   INFERENCE    John is an animal.
```

The question here isn't "what supports what" — it's "when did I learn this,
and what changed my mind after that."

7. The code view

The structure shown as exactly what it is — the JSON itself:

```json
{
  "nodes": [
    { "id": "n1", "text": "John is a dog.", "tag": "ASSUMPTION" }
  ],
  "relations": [
    { "from": "n1", "relation": "implies", "to": "n2" }
  ]
}
```

No interpretation at all. This is the view that proves the other views aren't
lying — when in doubt, look here.

This is where it starts resembling a notebook.
The important thing is that these are not ordinary text boxes.

They are views of actual nodes.

So when you edit a cell, you're editing the underlying structure.

This is why you can get a new type of notebook

Normal notebooks usually think:

```text
cell 1
cell 2
cell 3
cell 4
```

in a mostly linear order.

Riemann is saying:

> What if the cells are pieces of a connected structure?

Then you can have:

```text
QUESTION
   ↓
ASSUMPTION
   ↓
EVIDENCE
   ↓
INFERENCE
   ↓
CONCLUSION
```

And another branch:

```text
QUESTION
   ↓
ASSUMPTION
   ↓
OBJECTION
```

Now your notebook isn't just a stack of boxes.

It is a research structure.


```text
             ONE STRUCTURE
                  |
      ┌───────────┼───────────┐
      ↓           ↓           ↓
   document     graph       table
                  ↓
                cells
```

One source of truth.
The UI is therefore not the source of truth
