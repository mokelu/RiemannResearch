Right. I'm with you. With just SurrealDB tables and rows, you'd model them as records. So a variable is a record with a name and a value. An array is a record with a name and a list of values. An object is a record with properties. Functions could be records that store a name, inputs, and a definition. That's the core idea. We're not saying SurrealDB magically has variables built in. We're saying you can implement those ideas on top as persistent records. And that's exactly where your spreadsheet analogy fits. Each cell is a record. “price” just points to that cell. Then different engines can read or change that same cell without owning it.
