The CEP watches everything.

It watches the persistent language data structures defined at the database level: the variables, the functions, the sets, the matrices, the dictionaries. These borrowed variables being consumed by the engines are also reporting too. Everything sitting down in the shared database. It watches components. Key presses. Clicks. Scrolls. Pointer movement. Timers. File changes. Engine outputs. Variable mutations. Messages between selves. Deliveries. Anything any self or engine emits, the CEP sees it. It is all one stream.

Because it sees everything, the CEP can recognize anything. It can know a click happened. It can know a drag happened, because it watched the pointer go down here, move across, and come up there. It can know a hover, a double tap, a long press, a scroll that paused, a key held too long, a form abandoned halfway. None of that has to be wired in JavaScript. None of it has to be defined in HTML. The CEP just watches the raw stream and knows.

It can also know the slow things. That a button was clicked three minutes after a chart crossed its average. That an engine finished right after a file changed. That a variable became true and stayed true for ten seconds. That two selves both said the same thing within a minute of each other. JavaScript cannot see any of that. The CEP can, because it is watching time and it is watching the whole world at once.

So instead of writing onClick, onHover, onDrag, onDrop, onTimeout, we get something better. We get a world where everything is already reporting, and the CEP is already watching, and the only thing left to say is what we want to notice and what we want done.

That is the JavaScript-like event handling, except it is not limited to the page. It is event handling over the whole world.

And the persistent world is part of that world. Engines do not own their own state. They borrow from the persistent world. They read a variable, they write a variable, they call a function, they add to a set. Every one of those is an event. Every one of those goes into the same stream.

So the CEP is not just watching what users do. It is watching what engines do. It is watching what the persistent world does. When an optimization engine writes its result into a variable, the CEP sees it. When a query engine adds a row to a set, the CEP sees it. When a matrix is updated, when a function is called, when a dictionary gets a new key — the CEP sees all of it, because all of it is events in the same stream as clicks and keys and scrolls.

That is the thing that makes this different from JavaScript. In JavaScript, the DOM is the world and events happen to the DOM. Here, the persistent world is the world and events happen to the persistent world. The variables, the sets, the functions, the matrices are not just storage. They are live. They report. They are watched.

So now you can write things like: when this variable becomes true, when this set grows by more than a hundred, when this function returns, when this engine finishes, when this matrix crosses a threshold. None of those are events a browser knows about. But the CEP knows them, because the persistent world is reporting to the CEP the same way a button reports a click.

That is the whole picture. Components report. Engines report. The persistent world reports. Everything reports. The CEP watches. And what you write is only ever: this is what I want to notice, this is what I want done.

Because of this, you can compose e.g when this engine stop and this starts or when this file is done loading then use the X or y and the etc.
