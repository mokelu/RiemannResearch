## Python first

```text
hello.py                 → a single file
myapp/                   → a package (folder with __init__.py)
myapp + pyproject.toml   → a distributable app
```

In Python:

```text
a script     = one .py file
a package    = a folder of .py files
an app       = a package + metadata (name, version, deps)
```

When you `pip install requests`, you get a **package**. When you run `python hello.py`, you run a **file**. Both are "programs." The difference is scale.

## Spacetime equivalent

Same three levels:

```text
one_symphony.sy           → a single symphony file
patient_approval/         → a folder of symphonies + resources
patient_approval/ + manifest → a distributable spacetime app
```

So the answer to your question:

> **An app is a package, not a file. But a single file can be an app if it is small enough.**

## What a spacetime app package actually looks like

```text
patient_approval/
│
├── manifest.toml              ← who made it, what it needs, version
├── symphony.sy                ← the score (human-readable source)
├── program.stp                ← compiled rules (kernel-readable)
│
├── selves/                    ← optional: declared participants
│   ├── patient.toml
│   ├── doctor.toml
│   └── nurse.toml
│
├── ui/                        ← optional: if it has a screen
│   └── dashboard.html
│
├── resources/                 ← optional: files, schemas, data
│   └── patient_schema.json
│
└── README.md
```

That is the unit you write, share, and sell.

## The manifest — this is the important part

```toml
[app]
name = "patient_approval"
version = "1.2.0"
author = "Riemann Research"
description = "Admit, approve, and treat a patient."
entry = "program.stp"

[capabilities]
# what this app is allowed to touch in Space-Time
read  = ["Patient.*", "Doctor.*", "Nurse.*"]
write = ["Patient.status", "Ledger.*"]
tell  = ["Nurse", "Doctor"]

[engines]
# which engines it needs the orchestra to provide
requires = ["CEP", "Storage"]
optional = ["AI"]

[signature]
public_key = "..."      # so the kernel can verify it
signature  = "..."
```

The manifest is what the kernel reads **before** loading the program. If the app says it needs `Storage`, and Storage is missing, it does not load. If it asks for a capability the user has not granted, it does not load.

## The symphony file itself

```sy
# patient_approval/symphony.sy

Patient: When I am admitted, create my record.
Doctor:  When I approve the Patient, change the Patient's status to approved.
Nurse:   When the Patient's status becomes approved, tell me.
Nurse:   When I confirm treatment, change the Patient's status to being_treated.
System:  When the Patient's status changes, record it in the Ledger.
```

That is the source. It compiles to `program.stp`, which the kernel loads.

## So the whole picture

```text
SYMPHONY (.sy)         ← you write this
      ↓ compile
PROGRAM (.stp)         ← kernel runs this
      ↓ packaged with
MANIFEST (.toml)       ← declares capabilities, engines, version
      ↓ into
PACKAGE (folder)       ← you share / sell this
      ↓ installed into
SPACE-TIME             ← where it lives and runs
      ↓ shown by
MANAGER (dashboard)    ← what I stupidly built first
```

## What this means for your earlier question

> Where do you see 13 symphonies?

They are 13 **packages** installed in Space-Time. The Manager is just a window that lists them. The Manager is not the app. The Manager is a viewer.

> If you stop one, where is it?

Still installed. `patient_approval/` is still there. Its running instance is now `stopped`. You can start it again.

> Can someone make their own and sell it?

Yes. They write a `symphony.sy`, a `manifest.toml`, compile it, sign it, and publish the folder. A user installs it into their Space-Time, and the kernel verifies the signature and enforces the declared capabilities.

## The one-line answer

> **A spacetime app is a Python-style package: a folder containing a Symphony, its compiled program, a manifest, and optional UI and resources. A single `.sy` file is a symphony. A folder with a manifest is a spacetime app.**
