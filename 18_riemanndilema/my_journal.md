In september I told myself: I don't have the whole thing figured out yet, so we cannot ship.
And therefore we did not ship and now we lost.

Here are the september goals which in hindsight were possible:
1. 1000 users
2. Cursor but for traders
3. Start serious provider outreach once you had roughly 300–500 users and secure model/credit allocations for the October expansion.
4. Ship Riemann Research Notebook as a usable product.
5. Get the core workspace reliable: state/data persistence, connected/movable/executable blocks, smooth canvas surfaces, general artifact creation, and AI interaction with workspace objects.

Now october is showing the same fear in a new costume: “We don't know exactly what Riemann's expansion is yet, so maybe we can't move.”


But we can.

We already know the first move: ship Riemann Research Notebook, get users, keep shipping, and let the actual usage tell us which expansion matters most.

The danger is spending October doing the same thing September did: trying to completely understand the final Riemann before releasing the first useful Riemann.

October has four main goals:

1. Recovery
   Finish what September missed: ship Riemann Research Notebook and get it into real users’ hands.

2. Growth
   Target 25,000 users during October. Run the aggressive distribution effort continuously: directories, communities, newsletters, credit/grant sites, model providers, student/developer channels, etc.

3. Expansion
   Expand Riemann Research Notebook from the basic notebook into the broader research environment. That means starting concrete domains such as trading research, improving the workspace so AI can create/manipulate/execute things, and beginning the automation/object system that the old Abracadabra notes were pointing toward.

4. Research Engine / GTA 6
   Start the Optuna/Rust-tuner-style system where a user provides a problem, variables and target, and Riemann searches the space and returns useful results. Use game research/GTA 6 preparation as an early demonstration of that capability.

5.  Open source
    Open-source the appropriate core of Riemann Research Notebook so it can spread through GitHub, developer communities, directories, and contributors.

6.  Programming language
    Ship V1 of the Riemann/Abracadabra language: a small language for describing, creating, connecting, manipulating, and executing objects inside the notebook.

7.  TCPU
    Continue the main substrate/TCPU development.

8.  Transpiler
    Begin/ship the first versions of the TradingView, CTrader, and MT5 transpilers.

9.  Charts
    Make the chart layer a real part of the notebook and research environment: charts should be able to display, interact with, and work with research data/results.

Then the other old October items sit underneath these rather than being separate headline goals: TCPU/substrate development continues, Abracadabra V1 can begin, and the TradingView/CTrader/MT5 transpiler work can progress in parallel.

So the October scoreboard is simply:

**Recover → Grow → Expand → Prove the research engine.**
