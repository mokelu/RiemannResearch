1. **ID** — already covered: the immutable handle. Every platform on that list has one, even when it's invisible to the user (YouTube's video ID, Gmail's message-id, n8n's workflow ID, Obsidian's file path acting as a de facto stable reference).

2. **Name/title** — the human label, separate from the ID. TradingView chart layouts, YouTube videos, Gmail threads (subject line), n8n workflows, QuantConnect projects, fantasy leagues — every one of them has a string a person typed that has nothing to do with how the system actually finds the thing internally. This is the first proof that identity and identification are different: the ID is how the *system* finds it, the name is how the *person* finds it, and they're allowed to drift completely apart (rename a YouTube video a hundred times, the video ID never moves).

3. **Owner/creator reference** — a pointer to whoever made it. QuantConnect projects belong to a user, n8n workflows belong to a user or team, Gmail threads live in a mailbox, fantasy leagues have a commissioner, YouTube videos have a channel. This is the field that answers "whose is this" independent of who else can see or touch it — which is a different question from the next one.

4. **Created at / updated at** — the two timestamps that track the thing's own lifespan. Every single one of these platforms has both, because "when did this come into existence" and "when did it last change" are answering different questions — one is history, one is freshness.

5. **Status/state** — a small enum describing where the thing currently sits in its own lifecycle: n8n workflows are active/inactive, QuantConnect algorithms are draft/backtesting/live, YouTube videos are processing/public/private, fantasy leagues are pre-draft/in-season/complete. This is distinct from visibility — status is about *readiness*, not *who's allowed to see it*.

6. **Visibility/access** — public, private, unlisted, shared. YouTube literally has this exact three-way split. Gmail has sharing/delegation. n8n has team sharing. QuantConnect has private vs. public projects. TradingView ideas can be published or kept private. This is the axis status gets confused with, but it isn't the same thing — a video can be "public" (visibility) and still "processing" (status).

7. **Tags/labels** — freeform categorization independent of any folder structure. Gmail labels, YouTube tags, Obsidian tags, n8n workflow tags. Notice this is a different organizing axis than containment (item 9) — tags cut across categories, folders don't.

8. **The actual content/body reference** — a pointer to the real payload, which is usually stored separately from the identity record itself: the video file, the note's text, the workflow's node graph, the algorithm's source code, the email's message body. Identity records tend to be *thin* — they describe a thing, they rarely *are* the thing. This is worth sitting with, because it's the same instinct behind putting `.compiled` on a strategy rather than making the strategy record itself the DSL.

9. **Containment/parent-child structure** — most of these aren't flat. YouTube videos live in playlists (and playlists in channels). Gmail messages live in threads. n8n workflows contain nodes. QuantConnect projects contain files. Obsidian notes live in folders and link to each other. This is exactly your notebook→conversation→artifact nesting, and it shows up everywhere, which is a good sign it's not an idiosyncratic choice on your part.

10. **Last-accessed/last-run timestamp** — distinct from `updated_at`, this tracks *use*, not *edit*. n8n tracks last execution. QuantConnect tracks last backtest run. YouTube (for the creator) tracks last view spike. This is what would power "reopen where I left off" in your product — and it's the field I flagged as important for notebook a couple messages back, so it's good confirmation it's a real pattern, not something I invented for you.

If I had to compress this to the one thing every platform on your list independently arrived at: **identity is thin, content is thick, and everything else is metadata describing the relationship between the two** — who owns it, who can see it, what state it's in, what it's tagged as, and where it sits in the hierarchy. None of these platforms store the actual "stuff" on the identity record itself; they all keep a small stable pointer and let the heavy content live elsewhere, addressable through that pointer.
